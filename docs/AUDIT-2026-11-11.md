이 문서는 **아직 고치지 않은 항목**의 목록이다. 이미 고친 항목은 같은 PR의 커밋 메시지에 있다.

## 1. 금액이 틀리게 나오는 것 (우선순위 최상)

## 3. 눌러도 동작하지 않는 것

- 발주 상세: `updateOrder`가 없는 함수(`getData`, `saveOrderManual`)를 호출해 날짜·상태·메모 수정이 전부 실패. 수동 생성 발주는 상세 화면이 아예 깨짐(`items`가 문자열).
- 시스템 설정 저장: 경로에 id가 없어 404인데 성공 토스트. 안전관리비율 등 값은 견적 계산에 쓰이지도 않음.
- 검색·필터·정렬이 무동작인 화면: 수금, 세금계산서, AS, 미팅, 거래처, 계약, 지출, 공정표.
- 엑셀 내보내기: 노무비·지출은 빈 파일. CRM은 고객 테이블이 아니라 프로젝트에서 재구성.
- 백업/복원: 백업에 고객·노무비·지출·상담이 빠지고, 복원은 발주·AS·세금계산서를 무시. 전체 초기화는 일부만 지우고 성공 표시.
- `api()`가 실패해도 예외를 던지지 않아 저장 실패 시에도 "저장되었습니다"가 뜸 (세션 만료 포함).
- 미팅 등록 모달에서 메일/SMS 버튼을 누르면 작성 중인 미팅이 사라짐.
- 리포트 차트 이중 생성, 승인/삭제 후 화면이 먼저 갱신돼 이전 상태가 보임, 설계 일정 자동생성 중복.
- 미팅 알림 크론: Pages는 `scheduled` 핸들러를 실행하지 않는다 [확인 필요]. 메일 발신이 Resend 샌드박스 주소라 외부 고객에게 도달하지 않을 가능성 [확인 필요].
- 흉내만 내는 기능: "AI 계약서 검토"(고정 문구), 발주서 복사, 단가DB 업로드, 첨부 폴더 추가, 견적서의 은행 계좌(000-000000).
- 파이프라인 단계 "실주"가 🏆 아이콘에 "계약완료"로 매핑됨 (실주는 통상 수주 실패).

## 4. 비효율

- `ensureTables`가 로그인·`auth/me`·회사정보 조회마다 재실행 (요청당 D1 약 80회 낭비).
- 인덱스가 사실상 없음. 스키마 출처가 `migrations/`(20개 테이블)와 `ensureTables`(39개)로 이원화. `migrations/0004`는 운영 DB에 적용하면 실패한다.
- 부팅 시 28개 테이블을 LIMIT 없이 전부 로드. 사진·첨부 base64 포함. 첨부 2MB는 base64로 2.7MB라 D1 행 한도(2MB)를 넘는다 [확인 필요].
- `getOrders()`가 호출될 때마다 전 프로젝트 × 18공종 재계산. 대시보드 한 번에 수십 회.
- 입력 한 글자·슬라이더 한 칸마다 프로젝트 전체를 `INSERT OR REPLACE`. 순서가 뒤바뀌면 이전 상태가 저장될 수 있다.
- 수동 배포(`npm run deploy`)는 캐시 무효화 해시가 주입되지 않아 구버전 app.js가 남는다. CI만 처리한다.
- CI가 `wrangler@latest`를 써서 잠금 버전(4.66)을 무시한다.
