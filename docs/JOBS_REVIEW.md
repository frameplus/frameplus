## 1. 결론

| 질문 | 답 |

## 2. 근거

### 2-1. 명세서가 무엇인가
- 건설 현장 반장(58세 이상, 장갑 낀 손)이 **하루 일한 것을 기록하고 · 돈을 받고 · 공구와 사람을 구하는** 앱.
- 앱 37화면 + 웹 어드민 3화면, 하단 탭 6개(홈 · 캘린더 · 정산 · 중고장터 · 일자리찾기 · 전체).
- 심장은 03 계산 규칙: `gross = Σ(출근일×일급) + Σ(연장×시급) + Σ(청구 ON 경비)`, `tax = taxOf(gross, taxMode)`, `net = gross − tax`. 세액공제 4종(3.3% · 일용직 2.97% · 4대보험 ≈9.4% · 없음), 정산 규칙 4종(당일 · 주급 금요일 · 월말 · 익월 10일), 입금 자동 매칭 3단계.
- 명세 스스로 "06 권한 · 03 세액 계산이 가장 먼저 검증되어야 한다"고 명시 → 이번 1차는 03을 먼저 코드와 테스트로 고정했다.

### 2-3. 실제 사용 여부 — 두 관점

**사용자(반장) 관점 — 핵심 기능은 쓰인다.**
- 돈 문제(얼마 벌었나 · 못 받은 돈 있나)를 반장 본인이 직접 푼다. 대체재는 수첩 · 카톡 자기 채팅방 · 엑셀이며, 세액 3.3%를 뺀 실수령과 입금 예정일을 자동으로 계산해 주는 도구는 드물다.
- 55세 이상 사용성 조건(본문 15px↑ · 탭 44px↑ · 주요 버튼 60px · "공수" 대신 "출근")은 1차 코드에 토큰으로 반영했다.
- [가정] 파일럿 성공 기준: 주 3회 이상 기록 유지 50%↑, 월 1건 이상 청구서 발송 30%↑.

**운영자(프레임플러스) 관점 — 본업과 연결될 때만 의미 있다.**
- 프레임플러스 ERP의 **노무비(labor_costs)**와 JOBS의 **WorkLog**는 같은 사건의 양면이다(발주사 측 ↔ 반장 측). **협력 반장에게 먼저 쓰게 하면 ERP 노무비 입력이 반장 기록으로 대체**되어 사무 부담이 줄고, 시장 검증 비용이 0이다.
- 반대로 장터 · 일자리 · 채팅은 **운영 인력(신고 검토 · 분쟁 · 제재)을 상시 요구**한다. 10명 미만 조직에서 1인당 부담이 가장 큰 영역이며, 본업 GP율에 기여하지 않는다 → 보류.

### 2-6. 조직 부담 (10명 미만 기준)
- 1차 운영: 대표 1인이 주 2시간(파일럿 피드백 수집) — 가능.
- 2차(스토어 · 푸시): 개발 1인 3~4주 집중 — 본업 성수기(연말 이전 사무실 이전 시즌)와 겹치지 않게 배치 권장.

## 3. 액션 아이템

### 지금 당장 (이번 주)
1. **배포 설정** — Cloudflare Pages 환경변수 `JOBS_PUBLIC_ORIGIN=https://www.frameplus.kr`(또는 `https://frameplus-erp.pages.dev`), 기존 `SOLAPI_*` 그대로 사용. `JOBS_DEV_OTP`는 **운영에 절대 설정하지 않는다**(로컬 전용).
2. **D1 마이그레이션** — `npx wrangler d1 migrations apply frameplus-erp-production --remote` (또는 첫 요청 시 `ensureJobsTables`가 자동 생성).
3. **법무 문서 3건** 초안: 개인정보처리방침(휴대폰 · 사진 · 위치), 위치정보 이용약관, 서비스 이용약관 → 앱 설정 화면에 링크.
4. **위치기반서비스사업 신고** 서류 준비(방송통신위원회) [확인 필요: 법인 기준 신고 주체].
5. **파일럿 모집** — 협력 반장 3~5명 + 대표. 1개월. 측정: 기록 유지율 · 청구서 발송 수 · 입금 기록 수.

### 1~3개월
6. Capacitor 래핑 → Google Play(내부 테스트 트랙) → App Store. 푸시(퇴근 알람 · D-3 · 예정일 초과), 지오펜스 출근(S-04), 잠금화면 알림(S-05).
7. 사진 저장을 R2로 이전, EXIF 촬영 시각 · 좌표 읽기.
8. 카카오 알림톡 템플릿 2종(청구서 · 독촉) 심사, S-09 견적서 · S-16 전환 · S-15 연간 정산서(PDF).

### 검증한 것
- `npm test` 14/14 통과(견적 · 전환 · 연간 집계 포함), `npm run build` 통과(worker 약 250KB).
- 로컬 `wrangler pages dev` + D1에서 API 스모크 42단계 전부 통과(OTP 오류 처리, 필수값 검증, 중복 기록 409, 청구서에 들어간 기록 수정 차단 409, 입금 기록 있는 청구서 삭제 차단 409, 세액 재계산, 공개 청구서 HTML, 일부 입금 → 전액, 현장 세금 변경 «지난 기록에도 적용»).
- 390×844 헤드리스 크롬으로 로그인 → 현장 → 출근 기록 → 홈 → 캘린더 → 청구서 → 보내기 → 일부 입금 → 정산 탭 → 설정 → 공개 청구서까지 화면 전환 확인, JS 오류 0건.

### 명세와 다르게 한 것 (의도적)
- **하루 1건 규칙**을 "같은 현장 · 같은 날 1건"으로 완화 — 두 현장을 반일씩 뛰는 날을 막지 않기 위해 [가정].
- **예정일 초과 + 일부 입금**은 상태를 `overdue`로 둔다(남은 금액이 연체). 화면은 `paidAmount`로 "일부 입금"을 함께 보여 준다.
- **카카오톡 보내기**는 알림톡 템플릿 심사 전까지 문자로 보내며, 앱 안에 그렇게 표시했다.
- **소액부징수**(1,000원 미만)는 일용직도 청구 단위 합계로 적용 [가정].
